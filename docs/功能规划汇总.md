## 项目定位

**Game State Aware Agent（游戏状态感知 Agent）**  
不仅是 RAG 问答助手，更是实时监控游戏状态、主动播报告警、提供情境化建议的"圣安地列斯智能副驾驶"。

核心架构：
```
GTA SA 游戏进程
    ↓ (内存读取)
游戏数据采集层 (C++ ASI)
    ↓ (TCP 帧协议)
Agent 事件总线 (规则引擎 + 差分检测)
    ├─► 边沿触发事件 → 固定话术播报（低延迟）
    └─► 复杂场景 → LLM 生成个性化反馈 → TTS 输出
```

## 阶段 1：实时状态监控与告警播报 ⭐⭐⭐⭐⭐

**目标**：让 Agent 成为玩家的"战场观察员"，在关键时刻主动提醒。

### 1.1 生命/战斗状态

| 功能 | 数据来源 | 触发条件 | 播报示例 | 实现状态 |
|------|---------|---------|---------|---------|
| 血量告警 | `health` | 血量骤降 ≥25% | "血量掉得厉害，只剩{n}了，先脱离" | ✅ 已实现 |
| 濒死警告 | `health` | 血量 ≤15% | "血量见底了，赶紧找回血点" | ✅ 已实现 |
| 护甲破损 | `armor` | 护甲从 >0 变为 0 | "护甲碎了，注意掩体" | ✅ 已实现 |
| 子弹耗尽 | `ammo_total` | 当前武器弹药 = 0 | "没子弹了，换武器！" | ✅ 已实现 |
| 受击来源 | 伤害方向 | 连续被同一方向命中 | "背后有人！" | ✅ 已实现 |
| 死亡复盘 | `player_wasted` | 死亡状态位触发 | 播报死因 + 统计死亡次数 | ✅ 已实现 |

**技术细节**：
- 血量阈值按 `max_health` 百分比计算，适配升级后高血上限
- 护甲/弹药采用边沿触发（从有到无），避免重复播报
- 受击来源需同方向连续命中（6 秒窗口内同一攻击者 ≥2 次）才播报，背后方向优先报"背后有人！"
- 死亡复盘用 `times_wasted` 计数增量为触发信号，死因由 `m_nLastWeaponDamage`（eWeaponType）推断
- 冷却机制：同类事件冷却期内只播一次（血量 12 秒、护甲 20 秒、弹药 15 秒、受击 8 秒、死亡 5 秒）

```
1. 获取玩家当前坐标 (x, y, z)
```

**可标点资源类型**：
- 武器刷新点（319 个固定位置）

- 消警星点（Pay'n'Spray）

## 阶段 5：AI 伙伴人格（杀手级功能）⭐⭐⭐⭐⭐

**目标**：从工具升级为有性格的游戏伙伴。

### 5.1 人格模式切换

#### CJ 模式（老帮派兄弟）
```
语气：随性、街头化
示例：
- "兄弟，你现在装备太差，先去搞把 AK。"
- "这是咱们的地盘，别让 Ballas 看扁了。"
```

#### Sweet 模式（严肃大哥）
```
语气：严肃、责任感强
示例：
- "别忘了，我们是在保护 Grove Street。"
- "做事要有计划，别冲动。"
```

#### Catalina 模式（疯狂女友）
```
语气：暴躁、不耐烦
示例：
- "开快点！你是老太太吗？"
- "又死了？你行不行啊！"
```

## 数据管线设计

```
┌─────────────────────────────────────────────────────────────┐
│  GTA SA 游戏进程 (1.0 US HOODLUM)                            │
│  ├─ 内存地址：0x00B79380 (StatTypesFloat)                   │
│  ├─ 内存地址：0x00B79000 (StatTypesInt)                     │
│  └─ 内存地址：CPlayerPed + Offsets                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  C++ ASI 插件 (sa-agent\overlay)                            │
│  ├─ ReadPlayerState() 每帧调用                              │
│  ├─ 心跳定时器（3秒）推送完整状态                             │
│  └─ ToJson() 序列化为 JSON                                  │
└─────────────────────────────────────────────────────────────┘
                            ↓ (TCP Socket, 127.0.0.1:51678)
┌─────────────────────────────────────────────────────────────┐
│  Python 事件总线 (sa-agent\service\server.py)               │
│  ├─ handle_live() 接收 L 帧                                 │
│  ├─ check_events() 差分检测                                 │
│  │   └─ detect_events(prev, curr) → [(kind, text), ...]    │
│  ├─ 规则引擎：                                               │
│  │   ├─ 阈值触发（血量 <30%）                               │
│  │   ├─ 边沿触发（护甲 >0 → 0）                             │
│  │   └─ 节流/冷却（同类事件 12-20秒）                        │
│  └─ announce_event() 播报                                   │
│      ├─ broadcast_live_status(text) → P 帧 → HUD           │
│      └─ speech.say_sync(text) → TTS 输出                   │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  RAG Pipeline (可选，复杂场景)                               │
│  ├─ BM25 检索相关攻略                                         │
│  ├─ DeepSeek 生成个性化建议                                  │
│  └─ Segmenter 分句 → 边生成边朗读                            │
└─────────────────────────────────────────────────────────────┘
```

## 关键设计原则

1. **节流优先**：高频字段（坐标、速度）只用于内部判断，语音播报仅由边沿事件触发
2. **冷却机制**：同类事件在冷却期内只播一次，避免战斗中重复喊话
3. **忙碌保护**：玩家提问或听回答时，告警让路
4. **分层播报**：
   - 紧急告警：固定话术，低延迟（<100ms）
   - 情境建议：LLM 生成，高质量（1-2秒）
5. **渐进增强**：从基础告警 → 任务辅助 → 地图导航 → AI 伙伴，逐步迭代
