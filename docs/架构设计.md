# SA-Agent 架构设计

## 1. 项目定位

SA-Agent 是给《GTA: San Andreas》做的**实时游戏状态感知型 AI 助手**（Game State Aware Agent）。
它不是聊天机器人加一个游戏皮肤，而是三件事的组合：

1. **看得见** —— 从游戏进程内存里直接读玩家状态（血量、护甲、通缉、坐标、所在街区、
   手持武器、任务脚本、统计数值）与地面拾取物，采样即真相，不依赖 OCR 或截图推测。
2. **说得准** —— 以 GTA wiki 语料库为知识底座做混合检索（BM25 + 稠密向量 + RRF 融合），
   答案严格落在检索到的材料上，查不到就说查不到。
3. **接得上** —— 语音唤醒、语音提问、语音作答全程免键盘；紧急情况（血量骤降、
   通缉升星）由规则引擎主动开口，不必玩家先问。

最终形态是一个"坐在副驾上的老玩家"：玩家双手不离键鼠，喊一声「小龟J，这个任务怎么打」，
它结合当前处境和 wiki 知识给出口语化回答，必要时在雷达上打一个路点。

## 2. 总体架构

系统跨两个进程，靠本机 TCP（127.0.0.1:51678）连接。这条边界是刻意画的：
游戏是 32 位 MBCS 老程序，Python 生态（Whisper、fastembed、ONNX Runtime）在里面跑不动；
反过来，读游戏内存只能在游戏进程内做。于是各干各的，中间用最薄的协议对接。

## 3. 通信协议

两侧唯一的契约，定义在 `service/server.py` 的模块 docstring 里。

**帧格式**：小端 `uint32` 长度 + 1 字节类型 + UTF-8 载荷，其中
`长度 == 1 + len(载荷)`。上限 `MAX_FRAME = 1 MiB`，socket 开 `TCP_NODELAY`
（这些帧都小且要求低延迟，Nagle 攒包只会添乱）。

**C++ → Python**

| 类型 | 载荷 | 含义 |
|:---:|---|---|
| `Q` | 问题文本 | 文字提问 |
| `S` | 状态 JSON | 玩家状态快照，作为独立帧在 `Q` 之前发出；`{}` 表示本次无可用状态。非空的那一帧同时是"游戏正在进行中"的判据（见 6.1） |
| `V` | `start` / `stop` | 覆盖层按住左 Ctrl 的语音输入，识别结果回填输入框 |
| `G` | 拾取物 JSON 数组 | 整包替换服务端缓存 |
| `L` | `start` / `stop` / `heartbeat` | 实时语音问答控制；`heartbeat` 顺带捎上最新状态 |

**Python → C++**

| 类型 | 载荷 | 含义 |
|:---:|---|---|
| `T` | 文本片段 | 流式回答的一个 token |
| `D` | 空 | 本轮回答结束 |
| `E` | 错误描述 | 出错；约定在 `X` 之前发 |
| `X` | 识别文本 | ASR 结果（可能为空串，UI 据此结束"识别中"） |
| `W` | `"x,y,z"` | 请求覆盖层打一个雷达路点 |
| `P` | 阶段提示 | `recording` / `listening` / `thinking` / `q:<文本>` / `speaking` / `idle` |

**`idle` 是本轮唯一的结束标记**。`speaking` 只是阶段变化，收到它不能退出接收循环——
否则残留在缓冲里的 `idle` 会漏进下一轮，把状态机搞乱。C++ 侧的实时语音循环因此
显式地不在 `speaking` 上 break。

协议还有一条不对称性：`P` 和 `W` 可以由服务端主动发起（唤醒词那一路根本没有请求帧）。
所以 `client.cpp` 在空闲轮次里用零超时 `select()` 探一下（每轮至多取 8 帧），
不能只在"发过请求"之后才收。

## 4. 进程内 C++ 层（overlay/）

约 2,400 行第一方代码，编译成 `SAAgentOverlay.asi`。

### 4.1 加载与注入

以 ASI 插件形式落在游戏的 `scripts\` 目录，由已有的 ASI Loader
（中文化补丁的 `vorbisFile.dll` → `vorbisHooked.dll`）加载，不需要额外注入器。

`dllmain.cpp` 只有 34 行，但卸载路径的分支很关键：

```cpp
case DLL_PROCESS_DETACH:
    if (reserved == nullptr) overlay::Stop();      // 真正被 FreeLibrary
    else                     client::ShutdownSocket();  // 进程退出
```

进程退出时持有加载器锁，join 线程必死锁；但完全不管又会让服务端看到 RST。
折中是只做 `shutdown(SD_SEND)`，服务端收到干净的 EOF。

### 4.2 Hook 点

MinHook 挂 D3D9 设备虚表两个槽位：`EndScene`（索引 42）与 `Reset`（索引 16）。
`InitThread` 最多等 60 秒直到设备指针和窗口句柄都就绪才下钩子——游戏启动早期这两者都是空的。

`HookedEndScene` 里 ImGui 惰性初始化，且 **`PollLiveKey()` 在"是否渲染"的判断之前调用**，
这样即使某帧跳过绘制，按键也不会丢。

### 4.3 版本闸门与内存安全

所有游戏地址都是 1.0 US (HOODLUM) 版的静态地址（`gta_sa.exe`，
MD5 `170B3A9108687B26DA2D8901C6948A18`，14,383,616 字节）。换版本必然全错，
而错误的数据比没有数据更糟——它会被喂给模型。

版本判定用**指令特征码**而不是文件大小（后者被重打包一蒙就过）：

```cpp
// CWorld::FindPlayerSlotWithPedPointer (0x563FA0) 开头：
// 8B 54 24 04  mov edx,[esp+4]
// 33 C0        xor eax,eax
// B9 98 CD B7 00  mov ecx, offset CWorld::Players
const unsigned char expect[] = {0x8B,0x54,0x24,0x04,0x33,0xC0,0xB9,0x98,0xCD,0xB7,0x00};
```

这段特征一石二鸟：它同时证明了 `addr::Players == 0x00B7CD98`——地址就编码在指令里。
结果缓存，只算一次。

第二道防线是 `PlausiblePointer()`（区间 `[0x10000, 0x80000000)`）挡未初始化野指针；
第三道是整个 `ReadPlayerState()` 包在 `__try/__except` 里——读盘、切存档的瞬间指针会失效，
此时放弃本次采样、把 `valid` 置 false 就行。

### 4.4 数据采集（game.cpp / game.h）

关键地址（`game.h` 里每个都标注了交叉引用数作为证据）：

| 符号 | 地址 | 说明 |
|---|---|---|
| `RwD3D9Device` | `0x00C97C28` | D3D9 设备指针，371 处引用 |
| `WindowHandle` | `0x00C97C1C` | 主窗口 HWND |
| `UserPause` | `0x00B7CB49` | `CTimer::m_UserPause` |
| `Players` | `0x00B7CD98` | `CWorld::Players`（`CPlayerInfo[2]`） |
| `StatTypesFloat` | `0x00B79380` | 浮点统计量数组，索引 0–81 |
| `StatTypesInt` | `0x00B79000` | 整型统计量数组，索引 `(id - 82)` |
| `ScriptSpace` | `0x00A49960` | `$ONMISSION` = base + 409×4 = `0xA49FC4` |
| `ActiveScripts` | `0x00A8B42C` | 活动脚本链表头 |
| `Pickups` | `0x009788C0` | `CPickup[620]`，每项 `0x20` 字节 |
| `RadarSetCoordBlip` | `0x00583820` | 唯一的写操作入口 |

`ReadPlayerState()` 沿 `CPlayerInfo → CPlayerPed` 取血量（`+0x540`）、护甲（`+0x548`）、
载具指针（`+0x58C`）、武器数组（`+0x5A0`，13 槽 × `0x1C`）、当前槽位（`+0x718`），
坐标优先走 `m_matrix`（`+0x14`）里的 `CMatrix::pos`（`+0x30`），矩阵未分配时退回
`m_placement.m_vPosn`（`+0x04`）。金钱在 `CPlayerInfo+0xB8`，通缉星级在
内联 `CPlayerData` 的 `CWanted::m_nWantedLevel`（`+0x2C`）。

受击来源与死亡复盘另读三个 CPed 字段（偏移来自 plugin-sdk `VALIDATE_OFFSET`）：

- `m_fHeadingCurrent`（`+0x558`）—— 玩家朝向，弧度，0 = 北、顺时针增大，
  与 `describe_direction()` 的方位约定一致。
- `m_nLastWeaponDamage`（`+0x760`）—— eWeaponType，含非武器死因：
  49 车撞 / 50 车碾 / 51 爆炸 / 52 驾车枪击 / 53 溺水 / 54 坠落
  （数值与 gta-reversed `eWeaponType.h` 一致）。
- `m_pLastEntityDamage`（`+0x764`）—— 攻击者实体指针，取其坐标算攻击方向。
  该指针可能悬空（攻击者已被回收），坐标读取单独包一层 `__try`，
  失败只丢方向信息、不影响整帧状态。只读坐标、不传裸指针，避免跨帧悬空。

当前任务名的取法：`$ONMISSION` 为真时遍历活动脚本链表找 `m_bIsMission`
（`CRunningScript+0xDC`）为真的那一个，取它的 `m_szName`（`+0x08`）。
`m_szName` 是定长 8 字节、未必以 NUL 结尾，须手动截断；链表遍历带 128 次上限保护。
同一时刻至多一个任务脚本在跑，找到即停。

所在街区由 `zones.inc` 的轴对齐包围盒表查得。**嵌套 zone 取最后一个匹配项**，
与游戏本身的行为一致。

`ToJson()` 写进 2 KB 栈缓冲，坐标只留一位小数、距离换算成公里——
"过高精度反而增加 token 消耗"。

`ScanPickups()` 扫 620 个槽位，跳过 `pickupType == 0` 和 `IsDisabled()` 的项
（报一个已被捡走的点比不报更糟，玩家跑过去会扑空），只保留武器（模型表 36 项）、
护甲（模型 1242）、血包（模型 1240），并给每个点附上街区名。
`CPickup` 的坐标是 `CompressedVector`（`short[3]`，除以 8.0f 还原），
结构体有 `static_assert(sizeof(Pickup) == 0x20)` 兜底。

**`SetWaypoint()` 是全项目唯一会改动游戏状态的调用**：
`SetCoordBlip(BLIP_COORD=4, x, y, z, 0, BLIP_DISPLAY_BOTH=3, nullptr)`
再 `SetBlipSprite(handle, RADAR_SPRITE_WAYPOINT=41)`——画成玩家自己标路点的样子，
一眼就知道那是"去这里"而不是任务点。全局只留一个 blip 句柄，设新的之前先清旧的。

### 4.5 覆盖层 UI（overlay.cpp）

Dear ImGui + DX9/Win32 后端，`` ` ``（VK_OEM_3）开关，Esc 关闭。三处非常规设计都是被
游戏本身逼出来的：

**纯键盘操作**。`io.ConfigFlags |= ImGuiConfigFlags_NoMouse`，不画光标。原因是 SA 通过
DirectInput 独占鼠标，覆盖层拿不到可靠的鼠标位置。滚动用 PageUp/PageDown，
左 Ctrl 按住说话，F1 切状态面板。

**鼠标侧键靠轮询**。同样因为独占，`WM_XBUTTON*` 永远到不了 WndProc，
所以 `PollLiveKey()` 用 `GetAsyncKeyState(VK_XBUTTON1/2)` 在渲染线程里轮询。
这个函数顺便承担了心跳（3 s）、拾取物扫描（15 s）、路点出队三件事——
全在渲染线程上，正好满足"内存读取必须在游戏主线程"的约束。

**GBK 手工转码**。SA 是 MBCS 编译的，`WM_CHAR` 送来的是 GBK 双字节的
前导字节/后续字节，`WM_IME_CHAR` 也是。直接交给 ImGui 后端当 Unicode 处理，
中文会全变成 `?`。所以 `HookedWndProc` 自己拼字节、转 UTF-32 再喂给 ImGui，
然后吞掉输入消息不让游戏收到。字体用 `msyh.ttc` +
`GetGlyphRangesChineseFull` 加载中文字形。

实时语音另有一个 `DrawLiveHud()`：无边框 `NoInputs` 小窗贴在屏幕上方居中，显示
● 听着呢… / 思考中… / 回答中…，下面一行淡色的「听到：<识别文本>」。
覆盖层关着也能看见，这一路本来就不需要开界面。

### 4.6 网络线程（client.cpp）

状态、运行标志、socket 用原子量，共享缓冲共用一把互斥锁。渲染线程只
`Send()` 投递、`Snapshot()` 取文本，绝不做网络 I/O。

几个细节：

- 语音与实时语音的控制命令用 `std::deque` 而不是单槽位。快速连点时，
  单槽位会让 `stop` 覆盖掉还没发出的 `start`，结果麦克风一直开着。
  拾取物相反，只留最新一包。
- 会话循环按 语音 → 实时 → 拾取物 → 问题 的优先级处理，每类各有自己的
  "收到终止符为止"子循环。
- 断线时清空所有队列，并注入一个空识别结果，释放正在等待的 UI。
- `Snapshot()` 会**裁掉尾部不完整的 UTF-8 序列**。LLM 的 token 边界不对齐字符边界，
  不裁就会在 ImGui 里出现乱码方块。

## 5. 服务层（service/server.py）

834 行的中枢。asyncio 单事件循环负责帧分发，**所有阻塞工作（检索、ASR、TTS）
一律 `asyncio.to_thread` / `run_in_executor` 外抛**，必要时用 `queue.Queue` 在
线程与协程之间搭桥。事件循环一旦被 Whisper 阻住，心跳和播报就全停了。

### 5.1 事件规则引擎

心跳帧带来的状态与上一次做差分，`detect_events()` 产出 `(类别, 台词)` 列表：

| 触发 | 条件 | 类别 |
|---|---|---|
| 血量骤降 | 单次心跳内掉 ≥ 25% 最大血量 | `health` |
| 血量见底 | 跌破 15%（边沿触发，只报一次） | `health` |
| 护甲碎裂 | 由正变 0 | `armour` |
| 受击来源 | 同方向连续命中（6 s 窗口内同一攻击者 ≥2 次），背后优先报"背后有人！" | `hit` |
| 通缉升星 | 星级上升（≥4 星换更急的措辞） | `wanted` |
| 通缉解除 | 由正变 0 | `wanted` |
| 任务通过 | `missions_passed` 增加 | `mission` |
| 子弹耗尽 | 同一武器备用弹药由正变 0（非近战） | `ammo` |
| 死亡复盘 | `times_wasted` 增加，附死因（`m_nLastWeaponDamage` 推断） | `death` |

三重节流保证它不烦人：

1. **每次心跳至多播报一条**（`check_events()` 里 `break`）。
2. **分类冷却**：
   `ALERT_COOLDOWN = {health: 12s, armour: 20s, wanted: 8s, mission: 5s, ammo: 15s, hit: 8s, death: 5s}`。
3. **对话让路**：`announce_event()` 发现 `dialog_busy` 立即返回——玩家正在问问题时
   插嘴最讨人厌。

死亡事件排在 `detect_events()` 产出列表最前：死亡瞬间血量掉到 0，若让血量告警先报，
下一次心跳玩家已满血复活，这次死亡就再也不会被提起。

紧急播报走固定措辞而非 LLM，延迟 <100 ms；需要知识的回答才交给模型（1–2 s）。

### 5.2 拾取物空间查询

`G` 帧送来的清单缓存在服务端。`parse_nearest_intent()` 判断"最近的防弹衣在哪"
这类意图，刻意保守——必须先命中 `NEAREST_HINTS` 才继续；武器名不是靠关键词表匹配，
而是拿实时拾取物清单**反查**，这样它自动跟随 `game.cpp` 的 `WeaponName()`，
两边不会走偏。

距离只算**平面距离**（`math.hypot(dx, dy)`），带上 z 会让高架桥上下的点排错序。

`build_pickup_context()` 返回 `(线索, "x,y,z")` 并且**不直接作答**：线索被追加到问题后面
一起送进 RAG，让 wiki 的方位描述和实时距离融合成一句话。坐标则以 `W` 帧回传，
由渲染线程打点。

### 5.3 轮次令牌

`speak_token` / `next_speak_token()` / `cancel_speech()`：新一轮开始就自增令牌，
上一轮仍在流式生成的协程会发现令牌变了，停止往合成队列里塞句子。
`speak_reply()` 返回 `(文本, ok)`，`ok == False` 表示本轮已被顶替，
调用方**不能**再发 `idle`——那个结束标记属于新的一轮。

## 6. 语音子系统

### 6.1 三路语音，一支麦克风

| 入口 | 触发 | 帧 | 结果去向 |
|---|---|---|---|
| 覆盖层 | 按住左 Ctrl | `V` → `X` | 回填输入框，玩家可改再发 |
| 游戏内 | 鼠标侧键 | `L` → `P` | 直接生成 + 朗读，界面不必打开 |
| 唤醒词 | 说「小龟J」 | 无请求帧，服务端主动广播 `P` | 同上 |

三路共用一支麦克风，靠 `Mic`（包着 `voice.Recorder`）仲裁：录音前后
**引用计数式地暂停/恢复唤醒监听**。`WakeListener.pause()` 是真正关闭输入流
（`_pause_depth` 计数），不是只置个标志位——否则设备争用和"自己录到自己"都会发生。

**唤醒那一路只在游戏进行中开麦**。前两路要覆盖层发帧才会动，游戏没跑自然就没有；
唤醒是麦克风常开 + 每 0.7 秒跑一次识别，所以必须显式跟着游戏的起落走：

```python
game_active        # 覆盖层是否正在推有效状态帧
GAME_IDLE_TIMEOUT  # 15 s，断流多久算游戏停了
mark_game_active() # 收到非空 S 帧 -> 开麦
mark_game_idle()   # 断流 / 覆盖层断开 -> 关麦，并清掉会话缓存
game_watchdog()    # 每秒查一次断流
```

判据选 `S` 帧而不是 TCP 连接：`.asi` 在进程启动时就连上了，主菜单、片头、读盘
统统算"已连接"；而 `ReadPlayerState()` 只有版本对得上且真的进了存档才给出有效数据
（`valid`），覆盖层也只在那时才发 `S` 帧。附带的好处是游戏被切到后台时 `EndScene`
不再被调用，帧自然断流，麦克风跟着放开。

服务端仍然可以先于游戏启动：`voice.prewarm()` 照旧提前加载模型，
`enable_wake()` 只把 `WakeListener` 建好待命，`wake_sync()` 才决定开不开麦
（`start`/`stop` 可反复来回；`start()` 在挂起状态下不开流，避免游戏重开时
把上一轮还没念完的回答录进去）。`mark_game_idle()` 顺手把 `prev_state` /
`latest_state` / `latest_pickups` 清掉——换存档进来，`missions_passed` 一变
就会误报一句"任务通过"。

代价说清楚：版本闸门没过（非 1.0 US）时 `S` 帧永远不会来，唤醒词也就一直不开麦，
但按住左 Ctrl / 鼠标侧键的两路照旧可用。

### 6.2 ASR

16 kHz 单声道 float32，块长 1600 帧（100 ms），录音下限 0.3 s、上限 60 s。

**提问识别**（`LocalWhisper`）：faster-whisper `small`、int8、CPU，
`language="zh"`、`beam_size=5`、`vad_filter=True`。VAD 参数刻意放松
（`threshold=0.2`、`min_silence_duration_ms=1000`、`speech_pad_ms=800`）——
玩家边操作边说话，语速不稳、停顿长，严格 VAD 会把话截半。
`condition_on_previous_text=False` 避免上一句污染下一句，
另加一段较长的 `initial_prompt` 播种中文 GTA 专有名词。

**唤醒扫描**（`WakeScanner`）是**故意用另一套模型和参数**的：

```python
WAKE_WORD_DISPLAY   = "小龟J"
WAKE_WINDOW_SECONDS = 2.0     # 滑窗
WAKE_STRIDE_SECONDS = 0.7     # 步长
END_SILENCE_SECONDS = 1.2     # 说完判定
SILENCE_RMS         = 0.012   # SA_VAD_RMS 可调
# 模型 tiny、beam_size=1、vad_filter=False、cpu_threads=2
# initial_prompt 只放唤醒词本身
```

原因有两条，都是实测撞出来的：

- `small` + `beam=5` 处理一个 2 s 窗口要 2.5–3 s，滑窗会**永久落后**；
  `tiny` + `beam=1` 约 0.3 s，追得上。
- 那段长长的专有名词 `initial_prompt` 会把「小龟J」拽成「小规矩」，所以扫描器不用它。

唤醒判定用**同音头尾匹配**而不是精确串匹配（`WAKE_HEADS` 12 个变体 ×
`WAKE_TAILS` 一串同音字），ASR 对三字短语基本不可能字字正确。
`_take_pending()` 排空队列只保留最新窗口，避免积压；命中后把扫描窗口作为
`prefix` 传给 `_capture()`——一口气说完的问题不会被砍头。

### 6.3 TTS（speech.py）

Windows SAPI 走 COM（pywin32）。三个设计点：

- `clean_for_speech()` 先剥 markdown。SAPI 会把 `*` 和反引号念出来。
- `Segmenter` 边收 token 边断句：`_STRONG_END = "。！？!?；;\n"`、
  `_WEAK_END = "，,、：:"`、`_SOFT_LIMIT = 36`、`_MIN_SEGMENT = 4`。
  攒够一句就送去合成，这就是"边生成边说"的来源，首字延迟从整段生成时间
  降到第一句的时间。
- `SapiSpeaker` 用**一条专属线程**持有 COM 对象（STA 亲和性要求），命令走队列。
  但队列不够：线程已经阻塞在 `say_sync` 里时，排队的 `stop` 根本递不进去。
  所以打断走独立的 `threading.Event` 旁路，`_wait_done()` 用
  `WaitUntilDone(80)` 轮询，把打断延迟压在 ~80 ms。
  流式播放是 `begin` / `push`（不带 PURGE）/ `finish` 三段式，靠 SAPI 自己的播放队列衔接。

## 7. RAG 子系统（rag/）

### 7.1 语料流水线

`fetch_wiki.py` → `clean_wiki.py` → `embed.py`，三步全部可增量、可续跑。

**抓取**只走 MediaWiki API（网页和 S3 dump 都返回 403）。标题来源有四路：
`Template:Gtasa missions` 的 embeddedin、`Category:GTA San Andreas` 递归两层（ns=0）、
手工 `EXTRA_PAGES`，以及 `MAP_PAGES`——`Map:` 命名空间的 JSON 是唯一结构化的
收集品坐标来源。带节流、指数退避重试、gzip，50 个一批，`load_done()` 支持断点续抓。
产物 `data/raw/pages.jsonl`：1,982 页 / 13.6 MB。

**清洗**（`clean_wiki.py`，541 行，是整个流水线最脏的活）：

- `DROP_SECTIONS` 丢掉 Gallery / Trivia 之类噪声章节。
- `OTHER_GAME_SECTION` 正则剔除专讲其他 GTA 作品的章节——载具、武器、人物页面
  是跨作品共享的，不剔会严重污染；但提到 San Andreas 的一律保留。
- `PRIORITY_SECTIONS` 标记高价值章节，检索时加权。
- `GAME_ABBREV` 展开 `{{SA}}` 这类模板，直接删会留下"missions in ."这种残句。
- `extract_infobox()` 单独抽信息框——载具性能、武器伤害、任务奖励只存在于信息框里。
- `extract_map_markers()` 把 Map 命名空间的每个标记点变成独立可检索条目（含坐标）。
- 切块按段落边界，`--target 900` / `--overlap 120` / `--min-chars 80`，
  超长段落再按句子切，块间保留尾部重叠缓解语义割裂。

产物 `data/chunks.jsonl`：13,368 块 / 8.0 MB。

**向量化**（`embed.py`）：fastembed + ONNX Runtime，模型
`intfloat/multilingual-e5-large`（1024 维）。选它有两个理由：多语言（中文问、英文料）
以及不需要 torch（省掉约 2.5 GB 依赖）。e5 系列的 `"query: "` / `"passage: "`
前缀是必须的，缺了检索质量明显下降。

增量的关键是 `chunk_key() = sha256(MODEL_NAME + index_text(chunk))[:16]`：
块内容或模型一变，key 就变，只重编码变化的部分。
`index_text() = f"{title} — {section}\n{text[:800]}"`。

检索时是暴力矩阵乘 `self.vectors @ qv` 加 `argpartition`——13,440 × 1024 float32
约 55 MB，CPU 上毫秒级，FAISS / hnswlib 属于过度工程。
`VectorIndex.load()` 会把缓存行重排成当前块顺序；发现有块未编码就返回 `None`，
系统**静默退化为纯 BM25**而不是报错停摆。

### 7.2 混合检索（retriever.py）

**稀疏路**：`rank_bm25` 的 BM25Okapi。`tokenize()` = 英文单词/数字 + 中文逐字。
索引文本是「标题重复 3 遍 + 章节名 + 正文」——标题重复是最省事的标题加权手段。
另有两个乘数：`priority` 章节 ×1.25，标题命中别名 ×1.6。

**稠密路**：上节的 e5 向量，余弦相似度。

**融合**：RRF（Reciprocal Rank Fusion，`RRF_K = 60`）。用**排名**而不是分数融合，
因为 BM25 得分无上界、余弦在 [-1, 1]，两者的分数不可直接加权相加。
候选池取 `max(top_k * 8, 40)`，最后**同一标题最多留 2 块**，防止一个长页面刷满结果。

### 7.3 跨语言问题

这是本项目最核心的检索难点：**玩家说中文（还是语音识别出来的中文），
语料是英文 wiki**。三条战线同时打：

1. **别名表** `ALIASES`：`"大烟" → ["Big Smoke"]`、`"条子" → ["Tenpenny", "C.R.A.S.H.", "police"]`、
   `"怎么过" → ["walkthrough", "objectives", "strategy"]`。里面还专门备了
   ASR 同音兜底项：`"封狗"`、`"风狗"` 都指向 `Madd Dogg`，`"月铺"` 指向
   `Madd Dogg's Rhymes`。
2. **LLM 查询改写**（`REWRITE_SYS`）：中文问题 → ≤12 个英文关键词，
   提示词里含明确的同音字修复规则，例如
   「封狗多克的月铺」→「疯狗多克的乐谱」→ `Madd Dogg's Rhymes`。
3. **多语言稠密模型**：e5-large 本身就能跨语言对齐，是前两者漏掉时的兜底。

### 7.4 生成（pipeline.py）

DeepSeek `deepseek-chat`（走 OpenAI SDK，`base_url=https://api.deepseek.com`，
密钥读环境变量 `DEEPSEEK_API_KEY`）。三套系统提示词：

- `REWRITE_SYS` —— 查询改写，见上。
- `ANSWER_SYS` —— 文字回答。Grove Street 老炮口吻，≤200 字，
  **严格接地**：资料里没有就说没有，不许编；英文专有名词保留原文（玩家在游戏里
  看到的就是英文）。`max_tokens=600`。
- `VOICE_ANSWER_SYS` —— 语音回答。≤3 句 / 80 字，纯口语，禁止项目符号、
  编号、括号、markdown，专有名词只用中文名（SAPI 念英文很难听）。`max_tokens=200`。

`temperature=0.3`，流式返回。

`describe_state()` 把状态 JSON 渲染成中文塞进上下文。一个防幻觉细节：
任务脚本代号识别不出来时，它只说「正在进行任务」，**绝不把内部代号泄漏给模型**——
模型看到 `sweet1` 之类的字符串一定会编出一个任务名。

`load_env()` 用 `os.environ.setdefault`，真实环境变量优先于 `.env` 文件。

  （键是字符串的 CRC32）、`TDAT` NUL 分隔字符串。

`WIKI_ALIAS`（SCM 标题 → 实际 wiki 页名，如
`"Back to School" → "Driving School"`、`"Jizzy" → "Jizzy (mission)"`）、
`ACTIVITIES`（没有标题键的脚本，如 `bschoo`/`gym*`/`taxiodd`/`ambulan`/`firetru`/
`copcar`/`burgjb`/`freight`/`hotr`/`lowr`/`valet_l`/`impexpc`/`bcour`/`hj`/`pool2`/`cprace`）。
原则很明确：`mission_name()` 认不出来就返回 `None`，**不猜**。

向量数 13,440 = 13,368（wiki）+ 72（手写），两个语料共用一套索引。

## 9. 贯穿全局的设计原则

**最小侵入**。全项目只有一个会改动游戏状态的调用（雷达 blip）。其余全是只读。
崩了游戏就是崩了玩家的存档，这条底线不能碰。

**线程纪律**。内存读取和 blip 调用只在渲染线程（= 游戏主线程，SA 的逻辑与渲染
同帧串行，此时读不会与逻辑更新竞争）；socket I/O 只在网络线程；
asyncio 事件循环永不阻塞。

**宁缺毋滥**。版本不符 → 停用全部状态读取；块未编码 → 退化为纯 BM25；
任务代号认不出 → 返回 `None`；拾取物已被拿走 → 不报。
每一处都是"给出错误信息"比"给不出信息"更糟的判断。

**分层播报**。紧急事件用固定措辞，<100 ms；需要知识的走 LLM，1–2 s。
不为了统一而把急事拖慢。

**渐进增强**。麦克风没有、Whisper 没装、向量没跑，系统依然能用文字问答；
`SA_WAKE=0` 可以关掉唤醒词整条链路。

**边界处的细节都是踩出来的**。UTF-8 截断、GBK 转码、`deque` 而非单槽、
`idle` 单一终止符、`speaking` 不 break、扫描器降模型——这些在代码里都带着
原因注释，不是风格偏好。

## 10. 构建与运行

**C++ 侧**：`overlay/build.bat` → `vcvarsall x86` + CMake + Ninja Release。
CMake 里 `CMAKE_SIZEOF_VOID_P != 4` 直接 `FATAL_ERROR`（目标进程是 32 位，
编错架构比编译失败更难查）。C++17、静态 MSVC 运行时、`/utf-8 /W3`，
链接 `imgui minhook d3d9 imm32`，产物 `SUFFIX ".asi"` / `PREFIX ""`。
`build.bat` 里 `VSROOT` 是硬编码的（`D:\VSs\vs`），换机器要改。

**Python 侧**：`service/start.bat` 先 `chcp 65001` 再跑
`.venv\Scripts\python.exe server.py`。依赖见 `requirements.txt`，
全部锁定版本：openai 2.52.0、httpx 0.28.1、mwparserfromhell 0.7.2、
rank-bm25 0.2.2、jieba 0.42.1、fastembed 0.8.0、sounddevice 0.5.5、
faster-whisper 1.2.0、pywin32 312。

启动时 `main()` 会压掉 `httpx` / `faster_whisper` 的日志噪声、
`load_env()`、构建 `Pipeline()`、预热 SAPI 和 Whisper
（`speech.prewarm()` / `voice.prewarm(on_ready → enable_wake)`）、
起 `game_watchdog()`，端口占用（errno 48/98/10048）时打印
`Get-NetTCPConnection` 排查提示。模型加载完只是把唤醒监听建好待命，
真正开麦要等覆盖层推来第一帧有效状态（见 6.1）。

**配置项**（环境变量，敏感项只列名不列值）：

| 变量 | 作用 |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek 密钥，放 `.env`（已在 `.gitignore` 中） |
| `SA_AGENT_PROXY` | 可选代理 |
| `SA_WAKE` | `0` 关闭唤醒词 |

## 12. 能力边界

**已实现**：状态读取（约 37 个字段）、街区/城市定位、任务识别、
实时告警（血量骤降、血量见底、护甲碎裂、弹药耗尽、受击方向、死亡复盘、
通缉变化、任务通过）、
文字问答、三路语音、唤醒词、拾取物最近点查询与雷达标点、
wiki 知识库检索。

**明确不做 / 尚未做**（详见 `docs/功能规划汇总.md` 的 📋 项）：
载具起火/翻覆/爆胎、被甩出车外等第一阶段剩余告警；
第二阶段任务过程辅助（分步引导）；第三阶段完整寻路导航；
第四阶段成长与经济建议；第五阶段多人格（CJ / Sweet / Catalina）。

**结构性限制**，扩展前需要知道：

- 只支持 1.0 US (HOODLUM)。地址全是静态的，其他版本会被版本闸门直接挡下，
  不会崩但也不会有数据。
- Windows 专属。SAPI TTS 走 COM，GBK 转码依赖 MBCS 的 SA。
- 只读一个玩家槽位（`CPlayerInfo[0]`）。
- 依赖云端 LLM，DeepSeek 不通则问答不可用（告警仍可用，它不走模型）。

**扩展点**：新增状态字段 → `game.h` 的 `PlayerState` + `game.cpp` 的
`ReadPlayerState`/`ToJson`；若字段要进模型上下文（供 RAG 判断），再补
`pipeline.py` 的 `describe_state`——仅供事件检测用的内部字段
（如 `heading`、`last_damage_*`）不进，避免污染模型看到的描述；
新增告警 → `detect_events()` 加一条 + `ALERT_COOLDOWN` 加一个类别；
新增知识 → 追加 `data/custom.jsonl` 后跑 `embed.py`（增量，只编码新块）；
新增协议帧 → `server.py` 的分发表 + `client.cpp` 的会话循环，注意保持
`idle` 作为唯一终止符的约定。
